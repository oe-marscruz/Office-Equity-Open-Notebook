## Remaining implementation and reasons for handoff

1. **F05:** Replace `prepare-runtime.js`'s static POC assembly with the actual
   pinned frontend and locked backend dependencies. The real frontend requires
   Next.js server routes; current Rust packaging/serving expects static files.
   Resolve that integration explicitly, complete offline assets, record the full
   resolved inventory/tree hashes, and produce a native package. This work was
   not implemented. Native verification additionally needs a functioning Windows
   compiler/linker toolchain; no replacement toolchain was installed.
2. **F03:** Run the installed native package with synthetic markers and inspect
   launcher diagnostics, backend-owned files, crash handling and exports.
   This remains untested because no working native package was produced.
3. **F04:** Connect the migration workflow to native startup (Rust currently
   rejects legacy state before services start). Define and test least-privilege
   backend access, datastore encryption at rest, OS-protected keys, key/password
   rotation, and paired backup/restore/recovery. These controls require design
   and implementation; they are not supplied by the recovery fix or XOR
   obfuscation. Test fresh, legacy, missing/corrupt-secret, interrupted-rotation,
   restart and restore cases with the assembled application.
